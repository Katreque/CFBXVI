# Quartz Upgrades

Quartz v5 is vendored (copied without its git history) at a pinned upstream commit. See D-010.

**Current pin:** `jackyzha0/quartz` branch `v5` at `97a2d05f80c4c50534959b1d0d41cc4b3895625e` (2026-10-23).

## Not vendored

Upstream files we left out: `docs/` (Quartz's own documentation), `.github/`, `README.md`, `CODE_OF_CONDUCT.md`, `Dockerfile`, `content/`.

## Local changes to Quartz files

| File | Change |
|---|---|
| `.gitignore` | Removed the line that ignored `.gitignore` itself; added `pwa/` test output |
| `quartz.config.yaml` | Our site config (generated by `npx quartz create`, then edited) |

Everything else we add lives outside Quartz's files (`pwa/`, `docs/`, `content/`, `.github/`), so upgrades rarely conflict.

## How to upgrade

```sh
git remote add upstream https://github.com/jackyzha0/quartz.git   # once
git fetch upstream v5
OLD=97a2d05f80c4c50534959b1d0d41cc4b3895625e
git diff $OLD upstream/v5 -- . ':!docs' ':!content' ':!.github' ':!README.md' ':!CODE_OF_CONDUCT.md' ':!Dockerfile' > /tmp/quartz.patch
git apply -3 /tmp/quartz.patch      # resolve any conflicts it reports
npm i && npm i --prefix pwa
npx quartz build && npm --prefix pwa run build && (cd pwa && npx playwright test)
```

The PWA build fails loudly when an upgrade affects us:
- **A new CDN URL** in Quartz's output → add it to `vendor` in `pwa/config.mjs`.
- **A patch no longer matching** → update or remove it in `patches` in `pwa/config.mjs`.

Then update the pin above, add a short entry to `decisions.md` if behaviour changed, and commit (`chore: quartz upgraded to <sha>`).
