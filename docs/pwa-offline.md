# PWA & Offline

Quartz v5 has no PWA, service worker or offline support of its own, so we add it as a post-build step.

## What gets added

- **Web app manifest**: name, icons (192/512 plus maskable), `display: standalone`, `start_url` and `scope` set to the Pages subpath.
- **Apple tags**: `apple-touch-icon`, `apple-mobile-web-app-capable`, status bar style.
- **Service worker** generated by Workbox from the build output:
  - **Precaches the whole site**: every HTML page, JS/CSS file, image and `contentIndex.json` (search and the graph read from it, so both work offline).
  - Every file carries a content-hash revision, so an update downloads only the files that changed.
  - Navigation falls back to the cache when offline, which also covers Quartz's SPA routing (it fetches HTML pages).
- **Update prompt**: when a new version is installed, show "Novo conteúdo disponível — toque para atualizar".
- **Persistent storage**: call `navigator.storage.persist()` so the browser is less likely to evict the cache.
- **Install guide**: Android gets the native install prompt; iOS gets an in-app explanation of Share → "Adicionar à Tela de Início".

## Size budget

Estimated total: roughly 5–15 MB (Markdown plus WebP images) for 20 sections. That fits comfortably in iOS and Android quotas, so we precache everything on the first visit and don't need per-module downloads. CI will enforce a size budget (value to be set in Phase 3).

## Platform specifics

### iOS (Safari / WebKit)
- There is **no install prompt**. Users install manually from the Share menu, so onboarding has to explain it.
- **Storage eviction:** sites that are *not* installed can lose their storage after about 7 days without use. Installed home-screen apps are much safer. **Installing is part of onboarding, not optional.**
- **No background sync.** Content updates only when the app is opened while online.
- Only real-device testing shows eviction and install behaviour. Simulators aren't enough.

### Android (Chrome)
- Native install prompt (`beforeinstallprompt`).
- Generous quotas; `persist()` is usually granted for installed apps.

## GitHub Pages constraints

- Served from a **subpath** (`/<repo>/`). Quartz's `baseUrl`, the manifest `scope`/`start_url` and the service worker scope must all match it.
- Response headers can't be customised. Pages sends a short `Cache-Control` on `sw.js`, which is fine: browsers check `sw.js` for updates regardless.

## Origin change (future custom domain)

A PWA's storage and install are tied to its **origin**. Moving from `<user>.github.io` to a custom domain means:
- students have to install the app again from the new address;
- the new origin downloads the full precache again;
- the old installed icon keeps working, but it no longer receives updates.

Plan for the move: the base URL is a single config value; the release that changes the domain also ships a "Este app mudou de endereço — toque para reinstalar" banner on the old origin. See decision D-008.

## Testing

- Playwright: load the site, wait for the service worker, go offline, navigate several pages, use search and open the graph.
- Lighthouse in CI for installability and performance.
- Manual check on a real iPhone and a real Android phone before each student-facing release.
